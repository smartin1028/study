네, Feign Client에서 발생하는 SSL 오류에 대해 상세히 설명해 드리겠습니다. 이는 Feign을 사용해 HTTPS 통신을 할 때 매우 흔히 마주치는 문제입니다.

## Feign SSL 오류의 핵심 원인

Feign Client는 기본적으로 **"신뢰할 수 없는 인증서"** 또는 **"자체 서명된 인증서(Self-Signed Certificate)"**를 사용하는 서버에 연결하려고 할 때 SSL 핸드셰이크를 실패시키며 오류를 발생시킵니다. 이는 Feign이 내부적으로 사용하는 HTTP 클라이언트(기본값은 `Java's HttpURLConnection`, 보통은 `Apache HttpClient`나 `OKHttp`를 사용)의 기본 SSL 동작 방식 때문입니다.

### 대표적인 오류 메시지

*   `javax.net.ssl.SSLHandshakeException: PKIX path building failed: sun.security.provider.certpath.SunCertPathBuilderException: unable to find valid certification path to requested target`
    *   **가장 대표적인 오류입니다.** 클라이언트의 truststore(신뢰 저장소)에 서버의 SSL 인증서를 발급한 CA(Certificate Authority, 인증 기관)의 루트 인증서가 없어 발생합니다.
*   `javax.net.ssl.SSLPeerUnverifiedException: Hostname not verified`
    *   서버 인증서의 CN(Common Name)이나 SAN(Subject Alternative Name)이 연결하려는 호스트명(도메인)과 일치하지 않을 때 발생합니다.

## 해결 방법 (상세 설명)

문제를 해결하는 방법은 **"개발/테스트 환경"** 과 **"운영(Production) 환경"** 으로 나누어 접근해야 합니다.

### 1. 개발/테스트 환경 (자체 서명된 인증서 사용 시)

이 환경에서는 보안보다는 연결 자체를 이루는 것이 목표입니다. **운영 환경에서는 절대 사용하면 안 되는 방법들입니다.**

#### 방법 A: SSL 인증서 검증 비활성화 (가장 쉬운 방법,但 위험)

Feign은 내부적으로 `Client` 인터페이스를 사용합니다. `Apache HttpClient`를 사용한다면, SSL 검증을 무시하는 HttpClient를 Bean으로 등록하여 해결할 수 있습니다.

**1. Apache HttpClient 의존성 추가 (Maven)**
```xml
<dependency>
    <groupId>io.github.openfeign</groupId>
    <artifactId>feign-httpclient</artifactId>
    <version>11.8</version> <!-- 사용 중인 Feign 버전에 맞게 -->
</dependency>
```

**2. SSL 검증 무시하는 HttpClient Bean 생성**
```java
import org.apache.http.conn.ssl.NoopHostnameVerifier;
import org.apache.http.conn.ssl.SSLConnectionSocketFactory;
import org.apache.http.conn.ssl.TrustStrategy;
import org.apache.http.impl.client.CloseableHttpClient;
import org.apache.http.impl.client.HttpClients;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.context.annotation.Profile;

import javax.net.ssl.SSLContext;
import java.security.KeyManagementException;
import java.security.KeyStoreException;
import java.security.NoSuchAlgorithmException;

@Configuration
@Profile("dev") // 개발 환경에서만 활성화되도록 Profile 지정 (매우 중요!)
public class FeignConfig {

    @Bean
    public CloseableHttpClient feignClient() throws NoSuchAlgorithmException, KeyStoreException, KeyManagementException {
        // 모든 인증서를 신뢰하는 TrustStrategy 생성
        TrustStrategy acceptingTrustStrategy = (chain, authType) -> true;

        // SSL Context를 생성하고 위에서 만든 '모든 것을 신뢰하는' 전략을 적용
        SSLContext sslContext = org.apache.http.ssl.SSLContexts.custom()
                .loadTrustMaterial(null, acceptingTrustStrategy)
                .build();

        // 호스트명 검증도 무시하는 Socket Factory 생성
        SSLConnectionSocketFactory csf = new SSLConnectionSocketFactory(sslContext, NoopHostnameVerifier.INSTANCE);

        // 위에서 설정한 Socket Factory를 사용하는 HttpClient 생성
        return HttpClients.custom()
                .setSSLSocketFactory(csf)
                .build();
    }
}
```

#### 방법 B: 서버의 SSL 인증서를 Java Truststore에 추가 (더 안전한 방법)

서버가 사용하는 인증서(또는 루트 CA 인증서)를 클라이언트 JVM의 신뢰 저장소(`cacerts`)에 추가하는 방법입니다.

1.  **인증서 추출 (.cer 파일 얻기)**
    *   브라우저로 해당 서비스에 접속 → 주소창의 자물쇠 아이콘 클릭 → "인증서" 조회 → "인증서 경로"에서 최상위 루트 인증서 또는 직접 서버 인증서를 **DER 형식으로 바이너리(.cer)** 로 저장합니다.
    *   또는 OpenSSL 명령어 사용: `openssl s_client -connect <호스트명>:<포트> -showcerts </dev/null | openssl x509 -outform DER > mycert.cer`

2.  **Java Truststore에 인증서 추가**
    *   JDK/JRE가 설치된 디렉토리의 `lib/security/cacerts` 파일이 기본 truststore입니다.
    *   keytool 명령어 실행:
        ```bash
        keytool -import -alias my-local-cert -keystore %JAVA_HOME%/lib/security/cacerts -file mycert.cer
        ```
    *   기본 truststore 비밀번호는 `changeit`입니다.
    *   **주의:** 이 방법은 모든 애플리케이션에 영향을 미치므로, 다른 방법을优先하는 것이 좋습니다.

3.  **특정 애플리케이션만 별도의 Truststore 사용**
    *   인증서를 새 truststore 파일(`mytruststore.jks`)에 import합니다.
    ```bash
    keytool -import -alias my-local-cert -keystore mytruststore.jks -file mycert.cer
    ```
    *   애플리케이션 실행 시 JVM 옵션으로 해당 truststore를 지정합니다.
    ```bash
    java -Djavax.net.ssl.trustStore=/path/to/mytruststore.jks -Djavax.net.ssl.trustStorePassword=myPassword -jar myapp.jar
    ```

### 2. 운영 환경 (권장되는 방법)

운영 환경에서는 보안을 위해 반드시 **유효한 공인 인증서**를 사용해야 합니다. Let's Encrypt와 같은 서비스를 통해 무료로 발급받을 수 있습니다.

*   **Feign Client 측에서는 특별한配置를 할 필요가 없습니다.**
*   서버의 SSL 인증서가 **공인된 CA (DigiCert, Let's Encrypt, GoDaddy 등)에 의해 발급되었다면**, 클라이언트의 JVM은 이미 해당 CA의 루트 인증서를 `cacerts`에 보유하고 있기 때문에 SSL 핸드셰이크가 자연스럽게 성공합니다.
*   이것이 가장 정석적이고 안전한 방법입니다.

## 추가 문제 해결 팁

### Feign과 OkHttp 사용 시

`feign-okhttp`를 사용한다면, OkHttpClient를 similarly配置해야 합니다.

```java
import okhttp3.OkHttpClient;

import javax.net.ssl.*;
import java.security.KeyManagementException;
import java.security.NoSuchAlgorithmException;
import java.security.cert.X509Certificate;

@Bean
public OkHttpClient insecureOkHttpClient() throws NoSuchAlgorithmException, KeyManagementException {
    final TrustManager[] trustAllCerts = new TrustManager[] {
        new X509TrustManager() {
            @Override
            public void checkClientTrusted(java.security.cert.X509Certificate[] chain, String authType) {}
            @Override
            public void checkServerTrusted(java.security.cert.X509Certificate[] chain, String authType) {}
            @Override
            public java.security.cert.X509Certificate[] getAcceptedIssuers() {
                return new X509Certificate[0];
            }
        }
    };

    final SSLContext sslContext = SSLContext.getInstance("SSL");
    sslContext.init(null, trustAllCerts, new java.security.SecureRandom());
    final SSLSocketFactory sslSocketFactory = sslContext.getSocketFactory();

    OkHttpClient.Builder builder = new OkHttpClient.Builder();
    builder.sslSocketFactory(sslSocketFactory, (X509TrustManager)trustAllCerts[0]);
    builder.hostnameVerifier((hostname, session) -> true); // 호스트명 검증 무시

    return builder.build();
}
```

### Spring Cloud OpenFeign과 통합

위에서 생성한 custom HttpClient나 OkHttpClient Bean은 Spring Cloud OpenFeign에 의해 자동으로 감지되어 Feign Client에서 사용됩니다. 별도의 추가配置은 필요하지 않습니다.

## 결론

| 환경 | 권장 해결 방법 | 비고 |
| :--- | :--- | :--- |
| **개발/테스트** | **Custom HttpClient Bean을 이용한 SSL 검증 무시** | 구현이 빠르고 쉽습니다. `@Profile("dev")`로 제한해야 합니다. |
| **개발/테스트** | 별도의 Truststore 파일 사용 및 JVM 옵션 지정 | 다른 애플리케이션에 영향을 주지 않아 더 깔끔합니다. |
| **운영** | **공인 인증 기관(CA)에서 발급받은 유효한 인증서 사용** | **유일한 올바른 해결책입니다.** 보안과 안정성을 보장합니다. |

문제가 발생했을 때는 **1) 오류 메시지를 정확히 확인**하고, **2) 사용 중인 Feign Client의 구현체(`HttpURLConnection`, `Apache HttpClient`, `OkHttp`)가 무엇인지 확인**한 후, **3) 해당 환경(개발/운영)에 맞는 적절한 해결 방법을 선택**하는 것이 중요합니다.
