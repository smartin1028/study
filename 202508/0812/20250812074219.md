# 스프링부트 스케줄 배치 사용법

스프링부트에서 스케줄링과 배치 처리를 함께 사용하는 방법에 대해 상세히 설명드리겠습니다.

## 1. 기본 설정

### 의존성 추가
```gradle
// build.gradle
dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-batch'
    implementation 'org.springframework.boot:spring-boot-starter-quartz' // 선택적
}
```

```java
    // Job과 Step 정의
}
```

## 2. 스케줄링 설정

### 기본 스케줄링 활성화


## 3. 스케줄링 배치 구현 방법

### 방법 1: @Scheduled와 JobLauncher 사용
```java
@Service
public class ScheduledBatchService {
    
    @Autowired
    private JobLauncher jobLauncher;
    
    @Autowired
    private Job myBatchJob;
    
    @Scheduled(cron = "0 0 2 * * ?") // 매일 새벽 2시 실행
    public void runBatchJob() throws Exception {
        JobParameters jobParameters = new JobParametersBuilder()
            .addLong("time", System.currentTimeMillis())
            .toJobParameters();
        
        jobLauncher.run(myBatchJob, jobParameters);
    }
}
```

### 방법 2: Quartz 스케줄러와 통합 (더 복잡한 스케줄링 필요시)
```java
@Configuration
public class QuartzConfig {
    
    @Autowired
    private ApplicationContext applicationContext;
    
    @Bean
    public JobDetail jobDetail() {
        return JobBuilder.newJob(QuartzJobLauncher.class)
            .withIdentity("myBatchJob")
            .storeDurably()
            .build();
    }
    
    @Bean
    public Trigger jobTrigger() {
        return TriggerBuilder.newTrigger()
            .forJob(jobDetail())
            .withIdentity("myBatchJobTrigger")
            .withSchedule(CronScheduleBuilder.cronSchedule("0 0 2 * * ?"))
            .build();
    }
}
```

## 4. 배치 Job 정의 예제

```java
@Configuration
public class MyBatchJobConfig {
    
    @Autowired
    private JobBuilderFactory jobBuilderFactory;
    
    @Autowired
    private StepBuilderFactory stepBuilderFactory;
    
    @Bean
    public Job myBatchJob() {
        return jobBuilderFactory.get("myBatchJob")
            .start(step1())
            .next(step2())
            .build();
    }
    
    @Bean
    public Step step1() {
        return stepBuilderFactory.get("step1")
            .<Input, Output>chunk(100)
            .reader(reader())
            .processor(processor())
            .writer(writer())
            .build();
    }
    
    // reader, processor, writer 정의 생략
}
```

## 5. 고급 설정

### 배치 실행 제어
```java
@Scheduled(fixedDelay = 5000)
public void runBatchJobConditionally() throws Exception {
    if (shouldRunBatch()) {
        JobParameters params = new JobParametersBuilder()
            .addString("JobID", String.valueOf(System.currentTimeMillis()))
            .toJobParameters();
        
        jobLauncher.run(myBatchJob, params);
    }
}
```

### 병렬 처리
```java
@Bean
public TaskExecutor taskExecutor() {
    ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
    executor.setCorePoolSize(5);
    executor.setMaxPoolSize(10);
    executor.setQueueCapacity(25);
    return executor;
}

@Bean
public Step parallelStep() {
    return stepBuilderFactory.get("parallelStep")
        .<Input, Output>chunk(100)
        .reader(reader())
        .processor(processor())
        .writer(writer())
        .taskExecutor(taskExecutor())
        .throttleLimit(5)
        .build();
}
```

## 6. 주의사항

1. **JobParameter 고유성**: 매 실행마다 고유한 JobParameter를 사용해야 재실행이 가능합니다.
2. **트랜잭션 관리**: 배치 처리 중 오류 발생 시 롤백을 고려해야 합니다.
3. **실행 중복 방지**: `@Scheduled`는 기본적으로 중복 실행을 방지하지 않으므로 필요시 추가 로직 구현이 필요합니다.
4. **로그 관리**: 대용량 배치 처리 시 로그가 많아질 수 있으므로 적절한 로깅 전략 수립이 필요합니다.
