로컬 Jenkins에서 Maven 빌드 후 `.m2/repository`로 JAR 파일을 이동하는 방법에 대해 상세히 설명드리겠습니다.

## 1. 기본 개념 이해

### Maven 기본 동작
- Maven은 기본적으로 빌드 후 `target/` 디렉토리에 JAR/WAR 파일을 생성
- 동시에 `.m2/repository`에 의존성과 아티팩트를 자동으로 설치
- `mvn install` 명령어가 이 과정을 수행

## 2. Jenkins Pipeline 설정 방법

### Jenkinsfile 예제 (Declarative Pipeline)

```groovy
pipeline {
    agent any
    tools {
        maven 'M3'  // Jenkins에 설정된 Maven 도구 이름
    }
    stages {
        stage('Checkout') {
            steps {
                git branch: 'main', url: 'https://github.com/your/repo.git'
            }
        }
        stage('Build') {
            steps {
                sh 'mvn clean package'
            }
        }
        stage('Install to Local Repository') {
            steps {
                script {
                    // 프로젝트 정보 읽기
                    def pom = readMavenPom file: 'pom.xml'
                    def artifactId = pom.artifactId
                    def version = pom.version
                    def packaging = pom.packaging ?: 'jar'
                    
                    // JAR 파일 경로
                    def jarFile = "target/${artifactId}-${version}.${packaging}"
                    
                    // .m2/repository로 복사
                    sh """
                        mkdir -p ~/.m2/repository/${pom.groupId.replace('.', '/')}/${artifactId}/${version}/
                        cp ${jarFile} ~/.m2/repository/${pom.groupId.replace('.', '/')}/${artifactId}/${version}/
                    """
                    
                    // POM 파일도 함께 복사
                    sh """
                        cp pom.xml ~/.m2/repository/${pom.groupId.replace('.', '/')}/${artifactId}/${version}/
                    """
                }
            }
        }
    }
    post {
        always {
            // 빌드 후 정리 작업
            cleanWs()
        }
    }
}
```

## 3. Scripted Pipeline 방식

```groovy
node {
    stage('Checkout') {
        git 'https://github.com/your/repo.git'
    }
    
    stage('Build and Install') {
        // Maven 설치 실행 (자동으로 .m2/repository에 설치됨)
        sh 'mvn clean install'
    }
    
    stage('Verify Installation') {
        script {
            def pom = readMavenPom file: 'pom.xml'
            def localRepoPath = "/Users/yourusername/.m2/repository/${pom.groupId.replace('.', '/')}/${pom.artifactId}/${pom.version}"
            
            // 설치 확인
            if (fileExists("${localRepoPath}/${pom.artifactId}-${pom.version}.jar")) {
                echo "JAR 파일이 성공적으로 로컬 저장소에 설치되었습니다: ${localRepoPath}"
            } else {
                error "JAR 파일 설치 실패"
            }
        }
    }
}
```

## 4. Maven 설정을 통한 방법

### pom.xml에 리포지토리 설정 추가

```xml
<distributionManagement>
    <repository>
        <id>local</id>
        <name>Local Repository</name>
        <url>file://${user.home}/.m2/repository</url>
    </repository>
</distributionManagement>
```

### settings.xml에 로컬 리포지토리 설정

```xml
<settings>
    <localRepository>/Users/yourusername/.m2/repository</localRepository>
</settings>
```

## 5. Jenkins 빌드 후 작업 (Post-build Actions)

### "Execute shell" 빌드 후 단계 사용

```bash
#!/bin/bash

# 프로젝트 정보 추출
GROUP_ID=$(mvn help:evaluate -Dexpression=project.groupId -q -DforceStdout)
ARTIFACT_ID=$(mvn help:evaluate -Dexpression=project.artifactId -q -DforceStdout)
VERSION=$(mvn help:evaluate -Dexpression=project.version -q -DforceStdout)
PACKAGING=$(mvn help:evaluate -Dexpression=project.packaging -q -DforceStdout)

# 경로 생성 (groupId의 .을 /로 변환)
GROUP_PATH=$(echo $GROUP_ID | tr '.' '/')
TARGET_DIR="$HOME/.m2/repository/$GROUP_PATH/$ARTIFACT_ID/$VERSION"

# 디렉토리 생성
mkdir -p $TARGET_DIR

# JAR 파일 복사
JAR_FILE="target/$ARTIFACT_ID-$VERSION.$PACKAGING"
if [ -f "$JAR_FILE" ]; then
    cp "$JAR_FILE" "$TARGET_DIR/"
    echo "JAR 파일이 성공적으로 복사되었습니다: $TARGET_DIR"
else
    echo "JAR 파일을 찾을 수 없습니다: $JAR_FILE"
    exit 1
fi

# POM 파일도 복사
cp pom.xml "$TARGET_DIR/"
```

## 7. 주의사항 및 모범 사례

1. **권한 문제**: Jenkins 사용자가 `.m2/repository`에 쓰기 권한이 있는지 확인
2. **경로 확인**: 로컬 Maven 저장소 경로가 정확한지 확인 (`echo $HOME/.m2/repository`)
3. **의존성 관리**: `mvn install`은 의존성까지 모두 설치하므로 단순 JAR 복사보다 권장
4. **버전 충돌**: 동일 버전의 아티팩트가 이미 존재할 경우 덮어쓰기 됨

## 8. 문제 해결

### 일반적인 문제와 해결 방법

```bash
# 권한 문제 해결
sudo chown -R jenkins:jenkins ~/.m2/repository

# 경로 확인
echo "Maven local repository: $(mvn help:evaluate -Dexpression=settings.localRepository -q -DforceStdout)"

# 빌드 실패 시 디버깅
mvn clean install -X
```

가장 간단하고 권장하는 방법은 **`mvn clean install`** 명령어를 사용하는 것입니다. 이 명령어는 빌드와 동시에 로컬 Maven 저장소에 자동으로 아티팩트를 설치해줍니다.
